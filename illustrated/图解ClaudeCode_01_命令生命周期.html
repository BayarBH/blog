全局视角

Claude Code 表面上是一个终端 CLI 工具。但在内部，它是一个完整的 agentic system——一个拥有工具调用能力、权限控制、记忆系统和多智能体协调的自主代理。

一条用户命令从输入到完成，会穿越五个阶段。把这张图印在脑子里，它是理解整个系统的锚点：

接下来我们逐阶段拆解。

Phase 1 — Bootstrap

入口：main.tsx

一切从 main.tsx 开始。这个文件是整个 CLI 的入口点，使用 Commander.js 解析命令行参数，然后初始化 React + Ink 的终端渲染器。

但 Claude Code 在启动性能上做了一个关键决策：在任何重量级模块加载之前，先并行启动四个 side-effect。 

// main.tsx — 作为 side-effect 在其他 import 之前触发
startMdmRawRead()
startKeychainPrefetch()
MDM Settings
读取 Mobile Device Management 配置，用于企业环境下的策略控制
Keychain Prefetch
从 macOS Keychain 预取认证凭据，避免后续阻塞
API Preconnect
预建立与 Anthropic API 的 TCP/TLS 连接
GrowthBook Init
初始化特性开关系统，决定哪些功能对当前用户可用
设计决策：启动时间 = max(四个并行任务中最慢的那个)，而不是它们的总和。这就是为什么 Claude Code 的冷启动比你预期的快——它在你还没输入第一个字符的时候，已经在后台完成了鉴权和连接准备。

同时，重量级模块被延迟加载——OpenTelemetry（约 400KB）和 gRPC（约 700KB）通过动态 import() 在实际需要时才加载，而不是启动时。

Phase 2 — Context Assembly

系统提示词不是一个字符串

大多数 AI 应用的系统提示词是一个写死的字符串。Claude Code 的系统提示词是一台拼装机器。

context.ts 负责在运行时将多个来源的信息组合成最终的 system prompt。核心架构是一个分段缓存系统：通过 SYSTEM_PROMPT_DYNAMIC_BOUNDARY 标记，将提示词分为两部分——

  • 静态段（Static）：跨组织可缓存的通用指令，比如基础行为规则、工具使用规范。这些内容利用 Anthropic API 的 prompt caching 特性，避免重复计算。
  • 动态段（Dynamic）：每次会话变化的内容，包括当前项目的上下文、用户的权限模式、已连接的 MCP 服务器列表、从 memory 文件中读取的持久记忆。

动态段中有一个函数叫 DANGEROUS_uncachedSystemPromptSection()——名字里的 "DANGEROUS" 不是在开玩笑。它标记了那些你显式希望打破缓存的 volatile section。命名本身就是一种防御性编程：如果你用错了这个函数，名字会让你三思。

设计决策：系统提示词的缓存分界是 token 经济学的直接体现。静态段在 API 侧只计算一次，之后走缓存；动态段每次都重新计算。将内容放错区域意味着要么浪费 token（本该缓存的没缓存），要么看到过期信息（本该刷新的被缓存了）。

Phase 3 — Input Routing

两条路径

用户输入到达后，系统做一个简单的分流判断：

路径 A：斜杠命令。以 / 开头的输入走 commands.ts 的命令注册表。约 50 个命令——/commit 创建 git commit，/review 做代码审查，/compact 压缩上下文，/doctor 诊断环境问题。这些命令不经过 LLM，直接在本地执行。

路径 B：自然语言。其他所有输入走 QueryEngine——这是整个系统的核心引擎，负责与 Anthropic API 交互。这是一个 46,000 行的文件，处理流式响应、tool-call 循环、thinking mode、重试逻辑和 token 计数。

路径 B 是 Claude Code 作为 "agent" 的本质所在。接下来我们进入它的核心循环。

Phase 4 — Tool-Call Loop

这是整个 Claude Code 最重要的一个机制。如果你只记住一张图，记住这张：

循环的本质

Tool-call loop 是一个 while(true) 循环。每一轮的过程是：

  • 将当前对话历史（包括 system prompt、用户消息、之前的 tool 调用和结果）发送给 Anthropic API
  • 流式接收模型响应，逐 content_block 解析
  • 如果 content_block 类型是 text，直接流式输出到终端
  • 如果类型是 tool_use，进入权限检查 → 执行 → 结果回填
  • 将 tool_result 追加到 messages 数组，回到步骤 1

循环终止的条件很简单：当模型的响应中只包含 text 类型的 content_block，不再请求任何工具调用时，循环结束。

权限系统：安全边界

每次 tool_use 请求在执行前都会经过 toolPermission hooks 的拦截。Claude Code 支持多种权限模式：

模式 行为
default 交互式提示——用户逐个审批或拒绝每个工具调用
auto 基于 ML 分类器的自动审批，低风险操作自动放行
plan 计划模式——模型先规划再执行，用户审批整个计划
bypass 跳过所有权限检查（仅限受信环境）

每个工具的每个操作都被分类为 LOW、MEDIUM 或 HIGH 风险。.gitconfig、.bashrc、.zshrc 等敏感文件被特别保护，防止自动编辑。甚至有专门的路径遍历攻击防护——URL 编码遍历、Unicode 规范化攻击、反斜杠注入都有处理。

设计决策：安全性是从玩具到产品的分界线。Claude Code 不是简单地问"允许还是拒绝"，而是建立了一个完整的风险分类和上下文感知的权限系统。这也是为什么它有一个"权限解释器"——在用户审批之前，用另一个 LLM 调用来生成人类可读的风险说明。

工具注册表

Claude Code 拥有 40 多个工具，每个都是一个自包含模块，定义了输入 schema（Zod 验证）、权限模型和执行逻辑。核心工具包括：

工具 职责
BashTool Shell 命令执行（支持沙箱模式）
FileReadTool 文件读取（支持图片、PDF、Notebook）
FileEditTool 局部文件修改（字符串替换）
GrepTool 基于 ripgrep 的内容搜索
GlobTool 文件模式匹配搜索
AgentTool Spawn 子代理（递归调用整个循环）
MCPTool MCP 服务器工具调用
LSPTool Language Server Protocol 集成
WebFetchTool 抓取网页内容
WebSearchTool 网络搜索

Phase 5 — Output

三件事同时发生

当 tool-call loop 结束后，系统并行处理三件事：

终端渲染：Claude Code 使用 React + Ink 做终端 UI。没错，跟写网页一样用 React——只是渲染目标是终端而不是浏览器。约 140 个 Ink 组件构成了完整的终端交互界面。这大概是目前公开的最大规模 Ink 应用之一。

成本追踪：cost-tracker.ts 实时记录每次 API 调用的 token 消耗。输入 token、输出 token、缓存命中率都在追踪范围内。用户可以通过 /cost 命令查看累计消耗。

记忆巩固（autoDream）：这是最有趣的部分。Claude Code 有一个叫做 "Dream" 的后台记忆系统。它通过一个三重门控机制决定是否需要运行一次记忆巩固——24 小时时间间隔、至少 5 次会话间隔、成功获取一个并发锁。三个条件全部满足才会触发。

Dream 运行时，一个 fork 出来的子代理会执行四个阶段：定位记忆目录 → 收集近期信号 → 合并写入记忆文件 → 修剪和索引。这个子代理只有只读 bash 权限——它能看你的项目但不能改任何东西。它的工作纯粹是记忆整理。

递归：Sub-Agent 与多智能体

当模型在 Phase 4 中调用 AgentTool 时，整个 Phase 3→4→5 会被递归地 spawn 出来。子代理拥有自己的对话历史、自己的 tool-call loop、自己的权限检查。

在更高级的模式下，coordinator/ 模块接管。它将单个 agent 转变为一个协调者，管理多个并行工作的 worker agent。流程分四阶段：worker 并行调研 → coordinator 综合分析并编写规格 → worker 按规格实现 → worker 验证结果。

Worker 之间通过 XML 格式的 <task-notification> 消息通信，有一个共享的 scratchpad 目录用于持久化跨 worker 的知识。

设计决策：Agent swarm 的核心约束是"不要懒惰委派"。Coordinator 的提示词中明确禁止说"基于你的发现"——你必须实际读取 worker 的输出，然后精确指定下一步做什么。这是对多智能体系统中最常见失败模式的直接防御。

设计决策与启示

回顾整个生命周期，有几个架构决策值得记住：

并行优先。从启动时的四路并行预取，到 Output 阶段的并行渲染/计费/记忆，到多智能体的并行工作——整个系统在每一个层级都在追求并行化。

缓存是一等公民。系统提示词的静态/动态分段、工具 schema 缓存、GrowthBook 特性开关的 aggressive cache——token 是真金白银，每一个能省的 token 都不浪费。

安全不是附加功能。权限系统不是在 tool-call loop 之外的一个检查站，而是嵌入在循环内部的拦截链。每一次工具调用都过这条链，没有例外。

递归即扩展。AgentTool 让整个系统变得 fractal——一个 agent 可以 spawn 另一个 agent，后者有完整的工具集和权限。系统的能力通过递归而非添加新模块来扩展。
